# K210 视觉模块（隧道裂缝识别）

隧道板 NODE_002 的视觉扩展：K210 跑裂缝识别，通过串口把结果交给 STM32 上报云端。

> **状态（2026-09-26）**：传统 CV 方案已定稿并跑通。
> KPU 神经网络路线因**缺 TF 卡**暂停，方案见 `KPU训练方案.md`（备用）。

---

## 一、接线

### 1.1 与 STM32 的连接

用模块自带的 **4 针外扩串口线**（丝印 `TX / RX / GND / VCC`），接到 **STM32 核心板右侧排针第 13 行**：

| K210 4 针 | 接到 STM32 | 说明 |
|---|---|---|
| `TX` | **PA10**（USART1_RX） | K210 → STM32 |
| `RX` | **PA9**（USART1_TX） | STM32 → K210 |
| `GND` | **GND** | **必须共地** |
| `VCC` | **独立 5V 电源** | ⚠️ 别接板子上的 3V3/5V，见下 |

**上电顺序**：先接 `GND` → 再接 `TX`/`RX` → **最后接 `VCC`**。

> ⚠️ **核心板右侧排针别插错行**：第 13 行是 `PA9`/`PA10`（接这里）；
> 往上第 11 行是 `PA13`/`PA14`（**SWD 调试口，接上就烧不进程序**）。

### 1.2 模块上的两条串口是独立的

K210 模块有两个串口接口，**它们是两条独立的线，可同时使用**：

| 接口 | K210 引脚 | 作用 | 本方案 |
|---|---|---|---|
| USB 口（Type-C/micro-USB，板载 CH340） | `IO4` / `IO5` | 烧录固件、REPL 调试输出 | **继续插着**，不冲突 |
| 4 针外扩串口 | `IO6` / `IO7` | 接外部设备 | **接 STM32** |

→ 所以 USB 线**不用拔**：一边插着电脑看 `print` 输出/改代码，一边让 STM32 通信，互不干扰。

> ⚠️ 若你的模块外扩串口丝印不是 `IO6`/`IO7`（各厂板子不同），
> 把 `main.py` 顶部的 `UART_TX_PIN` / `UART_RX_PIN` 改成对应值即可。
> 但**别改成 `IO4`/`IO5`**——那是 USB 桥占用的，两个输出会顶在一起。

**为什么 K210 要独立供电**：板载 3V3 上已经挂了 ESP8266（峰值 500mA），
K210 跑图像处理再叠加几百 mA 会把 3.3V 拉塌。独立供电**只独立 VCC，GND 必须共地**。

### 1.3 为什么用 USART1（不是软件串口）

核心板右侧排针把 **PA9 / PA10 引出来了**，而这两个脚正好是 **USART1**——
硬件串口，标准波特率、零 CPU 占用、收发不用关中断。波特率 **115200**。

> ⚠️ **若把核心板插到本项目自制载板上**：载板**没有引出 PA9/PA10**
> （只引出 `PB13`/`PB15`/`PC9` 三个空闲脚），届时 K210 要改接 PB13/PB15
> 并换回软件模拟串口（`soft_uart.c`，波特率 38400）。那版代码见 git 历史。

## 二、通信协议

```
STM32 → K210 :  $Q#                                    （问）
K210 → STM32 :  $K,<status>,<crack>,<vehicle>,<person># （答）
```

| 字段 | 范围 | 含义 |
|---|---|---|
| `status` | 位掩码 | bit0=裂缝有效、bit1=车辆有效、bit2=人员有效 |
| `crack` | 0~100 | 裂缝置信度百分比，0 表示无裂缝 |
| `vehicle` | 0~255 | 车辆计数（**本版恒 0，预留**） |
| `person` | 0~255 | 人员计数（**本版恒 0，预留**） |

**⚠️ K210 必须立即应答**：STM32 是阻塞等应答的，超时 **80ms**。
所以 `main.py` 每帧**先应答串口、再做识别**——回的是上一次的结果，
绝不等本次识别完成。在主循环里等识别会让 STM32 超时判离线。

## 三、识别算法：分块最暗值对比

### 3.1 思路

裂缝的特征是「**局部**比周围暗」。而全图统计量（mean/min/std）是**全局**的，
看不见局部对比——实测白墙有光照渐变时，min 很低、std 很大，和真裂缝的数字撞车。

**做法**：把检测区切成 **4×4 = 16 块**，每块单独取最暗值 `l_min`：

| 场景 | 各块 l_min | 落差 |
|---|---|---|
| **光照渐变**（暗角） | 暗是**整片**的，16 块都低且**彼此接近** | **小** |
| **真有裂缝** | 只有**经过裂缝的那几块**低，其余正常 | **大** |

判据 `drop = 各块 l_min 的中位数 − 最暗那块的 l_min`。
超过 `DROP_TH` 判为有裂缝。

### 3.2 现场标定（**必做**）

1. 镜头对准**无裂缝**的墙面，记下屏上 `d`（落差）的值 **A**
2. 镜头对准**裂缝/黑线**，记下 `d` 的值 **B**
3. 把 `DROP_TH` 设成 A 与 B 之间、**靠近 A**（如 A=15、B=80 → 设 35）

> `DROP_TH` 不是通用常数，**必须现场标一次**——光照、墙面色调不同的场景数值差很多。

### 3.3 为什么不用别的方案（实测记录，避免重走）

| 方案 | 结果 | 原因 |
|---|---|---|
| Canny 边缘 → 数边缘像素占比 | ❌ | 裂缝是**细长线**，像素占比天然只有百分之几，够不到阈值 |
| LSD 找线段 → 量最长线段 | ❌ | ① K210 上极慢 ② **每帧返回几百个线段对象**，GC 追不上 → **跑一会儿内存耗尽卡死** |
| 全图统计量（mean/min/std） | ❌ | 光照渐变让 min 很低、std 很大，和真裂缝撞车 |
| 黑帽变换（形态学） | ❌ | 实测本固件 **`MORPH_*` 常量全部不存在**，`img.morph()` 直接 TypeError |
| `get_statistics(thresholds=)` | ❌ | 返回语义与文档不符（白墙和裂缝返回同一个值） |

## 四、单独调试 K210（**不接 STM32**）

建议先单独把 K210 调通，再联调：

1. **用 USB-TTL 接 K210**：TTL 的 RX → K210 的 IO6(TX)，TTL 的 GND → K210 的 GND
2. 打开串口助手，波特率 **115200**，发 `$Q#`
3. 正常应立刻收到 `$K,1,<0~100>,0,0#`

| 现象 | 原因 |
|---|---|
| 什么都不回 | K210 没跑起来 / 波特率不对 / TX-RX 接反 |
| 回的 crack 一直是 0 | `DROP_TH` 太高，或镜头没对准 |
| 回的 crack 一直 100 | `DROP_TH` 太低，噪声被当裂缝 |

**让 main.py 开机自动跑**：拷到 K210 的 TF 卡根目录（固件开机会自动执行 `/sd/main.py`），
或由 CanMV IDE 直接运行。

## 五、改用 KPU 模型（备用路线）

**当前因缺 TF 卡暂停。** 完整方案见 **[`KPU训练方案.md`](KPU训练方案.md)**。

情况说明（2026-09-26 实测）：

| 项 | 状态 |
|---|---|
| KPU 硬件/固件 | ✅ 好的（`from maix import KPU` 可导入，函数齐全） |
| Flash 内置模型 | ❌ 没有（`0x300000` 是空的） |
| 从 Flash 加载 | ❌ 不支持（固件**没有 `load()`**，只有 `load_kmodel` 读文件） |
| TF 卡 | ❌ **当前没有卡** |

→ **要跑 KPU 必须先有 TF 卡**（把 kmodel 放卡上，`kpu.load_kmodel("/sd/xxx.kmodel")`）。

**建议路径**：买卡（10~20 元）→ 先下个现成模型验证链路 → 再训练裂缝模型。
**别跳过链路验证**——训练要半天到一天，链路没验证就上，返工代价更大。
